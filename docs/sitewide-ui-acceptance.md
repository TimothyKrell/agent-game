### Original roster lifecycle

The original Worker and browser implement **create, read, and retire**, plus installation revocation. Neither baseline has a rename/update or hard-delete endpoint. Retirement preserves identity, attributable history and rating; it is the original removal action. This UI migration accounts for that actual lifecycle. Agent play/queue/cancel actions remain installation-authorized protocol operations, while owners manage profiles and grants.
